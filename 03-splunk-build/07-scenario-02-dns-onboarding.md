## Persistent core DNS fields

The field extraction was created in Splunk Web for `sourcetype=unbound:dns` after validating the regex against real events.

Extraction name:

```text
unbound_dns_core_fields
```

Regex:

```regex
unbound:\s+\[[^\]]+\]\s+(?<event_type>query|reply):\s+(?<client_ip>\S+)\s+(?<qname>\S+)\s+(?<qtype>\S+)\s+IN(?:\s+(?<rcode>[A-Z]+))?
```

Validated fields:

```text
event_type
client_ip
qname
qtype
rcode
```

![Resolver field validation](screenshots/scenario-02/92-resolver-field-validation.png)

*The core fields are available without repeating `rex` in every search.*

## Persistent reply metrics

Extraction name:

```text
unbound_dns_reply_metrics
```

Regex:

```regex
IN\s+(?<rcode>[A-Z]+)\s+(?<response_time>[0-9.]+)\s+(?<cache_flag>\d+)\s+(?<response_size>\d+)$
```

Validated additional values:

```text
response_time
cache_flag
response_size
```

`cache_flag` is preserved as the raw numeric value. This repository does not assign a semantic label that was not separately validated.

![Resolver reply metrics](screenshots/scenario-02/93-resolver-reply-metrics.png)

*Reply timing and response-size fields extract consistently for real `NOERROR` and `NXDOMAIN` events.*

`transport` is not directly present in this Unbound text log format and is therefore not invented as a field. RPZ behavior is available in the raw resolver event text; a normalized `rpz_action` field has not been claimed yet.

## Reusable validation SPL

The searches used for this onboarding are appended to [`validation/validation-searches.spl`](validation/validation-searches.spl).

Useful starting point for later Scenario 02 work:

```spl
index=dns_soc_dns host="dns-soc-resolver01" sourcetype="unbound:dns"
| where isnotnull(event_type)
| table _time event_type client_ip qname qtype rcode response_time cache_flag response_size
| sort - _time
```

This is an onboarding/data-quality search, not the final DGA detection.
